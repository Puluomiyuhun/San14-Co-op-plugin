## Actual lifecycle

1. Existing A native Prepare, owner arm, seven-source publication, parent initialization and typed Runtime observation execute first.
2. A-specific rules capture reuses the full existing Config sampler but validates the exact installed A sources and typed Runtime through `AObservedBoundary`. It does not demand B's original User/Game slots. The factory uses the same reader/API/process identity, shared native-call lock, unknown-safe call helper and original native Prepare/Seal/publisher.
3. Before the first Save, one rules activation is prepared, sealed and installed. The same activation stays installed through the first Save, Running, fresh User/Strategy return and second Save. Publish observations and formal B completion observations check the actual six-source rules owner again.
4. Native rules callbacks pin the same image/root/world/settings and resolve subjects dynamically. They do not retain the initial User/Strategy pointers or require the initial date on each callback. The original restore observer already permits forward date with all other Config fields unchanged. Thus ordinary same-world advancement needs no unprotected restore/reinstall interval. Root/world replacement remains rejected; this owner does not implement A reload.
5. Normal cleanup closes and drains local TLS observation callbacks, verifies/restores all six rules sources with zero active callbacks, then permits the existing A Stop/drain/seven-source restore. Modules remain loaded until process exit.

Lock order is Room → coordinator → shared native-call lock. Rules publication cannot overlap an A Snapshot remote call. Neither lock is an engine-wide input/execution fence.

Unknown native or publisher outcomes retain the factory/module/owner and suppress A Stop/restore. Even a known workflow failure may hold the Room, making subsequent rules capture refuse restoration; that conservatively retains all thirteen sources. Running cannot be described as drained merely because a Python exception occurred. Do not promise universal exception cleanup, clear once-claims, unload modules, or retry a held owner. Normal process exit remains the recovery boundary for retained unknowns.

`entry.status()['protection']` exposes actual `installed_once`, `restore_verified`, and `retained_or_unknown`, including a factory that loaded a module but failed before returning a port. Configuration alone never sets these success fields.
