# A Runtime typed DLL bootstrap

This successor adds callable local exports to the frozen `a_save_local_runtime` composition. It does not discover a game, publish instructions, submit a save by itself, or supply multiplayer admission. The parent coordinator and publisher own those steps.

## Executable interface

`a_save_runtime_exports.h` defines a Windows x64, little-endian, pack(1) ABI. Every in/out packet starts with magic `0x31585241`, version 1, exact `sizeof(packet)`, operation and initially zero result. The return code and output result must both be zero before the output is usable. The C++ schema executable emits actual compiler `sizeof` and `offsetof`, including nested types and array counts; Python must compare against it rather than assume alignment.

Eight exported `DWORD WINAPI(void*)` entry points are `ASaveRuntimePrepare`, `Plans`, `ArmOwner`, `ArmPublishedSources`, `Snapshot`, `Stop`, `StartServer`, and `ServerStatus` (each with the `ASaveRuntime` prefix). Operations are numbered 1–8 in that order. Prepare copies immutable native identity, approved cached-storage inputs, directories and planning binding. There are no caller-supplied callback addresses. All later packets carry the same nonzero 32-byte nonce. The nonce binds this local run, not remote authentication. Pipe requests retain the existing secret and packet validation.

Prepare is once-only after envelope/nonce/reserved validation. Even a real Runtime configuration failure consumes that attempt. Duplicate calls do not reset it. Concurrent bootstrap calls return Busy. Unknown remote-call outcomes must retain their buffers and objects and must not be retried as fresh operations.

Prepare produces plans through a separate Plans query. Owner Arm runs **before** changing inline bytes. The external publisher then writes Gate's two call sites and Parent's one call site. After releasing its debugger hold it calls ArmPublishedSources, which publishes Gate slots and arms Parent last. A naturally executed parent callback initializes the actual Controller and Host. Only the subsequent ready Snapshot permits StartServer. The server uses Runtime's exact same Owner and mailbox ports. No testing callback replaces them in this DLL.

**Do not call any export while other target threads are debugger-suspended.** Runtime/Owner snapshots and lifecycle methods take real locks. The instruction publisher performs only external reads/writes in its held window; it must detach before remote bootstrap/query calls. No exported function waits for the game to initialize Host, joins native work, or unlocks a producer lock from a foreign thread.

## Server and restoration lifecycle

StartServer copies the fixed pipe name/secret/client PID/timeout, creates a retained concrete Server and shutdown event, and starts one dedicated thread. Runtime's ConfigureTransport supplies actual submit/copy/permit/cancellation ports. End-of-connection Server.Run stops Owner; the thread then stops Runtime. Stop first signals shutdown and then stops Runtime/mailbox. ServerStatus reports resolved worker lifetime separately from Stop acceptance: `threadExited` also becomes true if the consumed start attempt failed before creating a thread, so cleanup never waits for a nonexistent worker. Such failures stop Runtime and do not reopen the attempt. Handles, modules, Runtime and Server remain retained until process exit; there is no unload export.

Snapshot uses the new `a_save_runtime_publish_*` production successors. Their bridge counter pointers refer to the actual User(2), Gate(3), Parent(2) banks. Their parent FINALLY caches Host state on its actual host thread. Snapshot brackets actual Runtime reports with stable counter/cache reads; busy callbacks return NotReady. It publishes a direct HostCache address for the external publisher's held-window revalidation. Caller-supplied output flags are overwritten.

`restoreReady` requires stopped Runtime/Owner, no lease/frame, no save lane or active scopes, and a known drained Driver terminal state. Once Host is initialized, its valid parent-thread cache is mandatory. Before initialization, no lease can have been taken: Host.Initialize never acquires the producer, and Parent marks hostInitialized before the first BeforeFrame. This specific pre-init case can therefore permit partial-install restoration without inventing a cache. It is only a candidate snapshot: the external publisher must still recheck actual counter activity, direct cache and source bytes under its own debugger hold. Stopping is not proof of complete input pause, all writers excluded, native work drained, or instructions restored. `productionPermit` and `allWritersProven` remain false.

The production build substitutes four explicitly named evidence TUs for frozen User/Gate/Parent banks and ParentAdapter. Frozen Runtime, Controller, Owner, Gate and Driver sources are unchanged. Parent successor adds only the host-thread cache capture; source diffs are the publisher agent's responsibility.
