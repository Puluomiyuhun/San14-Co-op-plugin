## Delivered and exact scope

- `b_reload_lifecycle_fault_guard.h/.cpp`: one successfully bound retained `Gate`, initialized with actual Provider generation, Session and InputController objects. `RegisterAndOpen(next)` reads their real reports plus the actual automatic Root receipts; failed/active/abnormal input, session or Root, absent matching Root tasks, or incomplete joins/planning/receipts refuse before calling Provider Register/OpenWindow. Matching Root task and ports generation/attempt/epoch must equal the Provider report. A consumed attempt is never retried or reset. Invalid Initialize/wrong-thread calls are non-consuming. Completed Session `stopRequested` is allowed only along with all completion receipts: frozen successful pipeline calls RestoreBeforeCommit→Stop after its load.
- `b_reload_lifecycle_fault_admission.inc`: owned fixture wraps the real HWBP observation callback and raises actual SEH `0xE014CF21` at its hardware-delivered call. The underlying observer catches it and creates its own Observer error receipt; the real InputController blocks queue submission. No error/uncertain/task completion fields are filled in by the fixture.
- `b_reload_lifecycle_fault_fixture.inc`: attempts next-generation admission through the real gate and verifies no Register/Open call, absent next Provider bank, and unmodified prior reports. Stops all four owned workers normally after contained observer failure.
- `b_reload_lifecycle_fault_test.py`: source-pinned archive fixtures; compiles guard and lifecycle production objects without fixture macros, then actual owned executable. Archive byte/business/constructor services remain explicit substitutes.

The Root owner itself is healthy for these cases: the observation exception is contained by the actual child VEH, so native User returns, Root gets 3 captures, no abnormal Root unwind is expected. This is not evidence for business SEH escaping the task, foreign DR preservation, or recovery/retry after uncertainty. Those earlier isolated tests have NOT been promoted into this four-worker/two-generation composition.

## Trust and concurrency boundary

This gate is a local host successor, NOT a global native scheduler fence. The trusted serialized host must supply the actual registered Provider/Session/InputController; public snapshots do not expose registration pointers and do not independently authenticate arbitrary object substitution. Root tuple checks bind the observations to the registered generation/attempt/epoch. Snapshot inspection and subsequent Register/Open are not one shared scheduler lock; callers must serialize/quiesce scheduling across the transition. A caller bypassing Gate and using frozen Provider APIs directly remains outside protection. Fixed schedulerFence/roomReady/fullWorld are false. No runtime installer, full input pause, writer drain, game save-load, two games, actual simulation or production permit is delivered.

Cold-start timing retains the predecessor limitation: the owned constructor waits until all four threads reach their initial waits; real game timing/installation is not established. The diagnostic second file is a byte-modified fixture, not a second legitimate game save. Actual constructor and engine/file effects are doubles.
